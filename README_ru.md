# r800zzXRdlnaServer

[English](README.md) | [Русский](README_ru.md) | [Español](README_es.md) | [ภาษาไทย](README_th.md) | [中文](README_zh.md) | [한국어](README_ko.md) | [日本語](README_ja.md)

DLNA-сервер для Windows, предназначенный для воспроизведения XR-видео на PICO, Meta Quest и других совместимых устройствах. Поддерживает удаление фона в реальном времени с помощью ИИ (RVM), вывод с альфа-каналом/хромакеем и преобразование видео.

**Для AI Passthrough в реальном времени требуется графический процессор NVIDIA.**

`r800zzXRdlnaServer` — это нативное приложение на C++. Оно напрямую использует библиотеки FFmpeg и не запускает Python или `ffmpeg.exe`.

## Возможности

- Передача через DLNA видео из выбранной папки и отдельно выбранных видеофайлов.
- Сохранение точного имени исходного файла в списке медиа DLNA.
- Поддержка обнаружения UPnP/DLNA и ContentDirectory для совместимых клиентов, включая DeoVR.
- Удаление фона видео в реальном времени с помощью Robust Video Matting (RVM).
- Поддержка Alpha Packed, настоящего альфа-канала WebM VP9 и зелёного хромакея.
- Встроенное автономное преобразование видео с ускорением на NVIDIA GPU и резервным режимом CPU.
- Простой встроенный видеоплеер Windows со звуком, перемоткой, паузой/воспроизведением, полноэкранным режимом и показом левой половины SBS.
- Автоматическое определение доступности NVIDIA CUDA/RVM/NVENC.
- Интерфейс на английском, русском, испанском, тайском, китайском, корейском и японском языках.
- Пользовательские настройки сохраняются в `%LOCALAPPDATA%`, а не в каталоге установки.

## Режимы вывода DLNA

| Режим | Вывод | Примечания |
| --- | --- | --- |
| Alpha Packed | HEVC/NVENC в MPEG-TS | Быстрый режим реального времени для совместимых XR-плееров. |
| Alpha WebM VP9 | WebM с настоящим альфа-каналом VP9 | Использует кодирование libvpx на CPU и может пропускать кадры, особенно для видео 4K/60. |
| Chroma Key | HEVC/NVENC с зелёным фоном | Используйте режим зелёного хромакея в принимающем плеере. |
| OFF | Исходный файл | Обработка RVM не выполняется, NVIDIA GPU не требуется. |

Интерпретация альфа-канала зависит от принимающего плеера. Клиент, не поддерживающий выбранный альфа-формат, может показывать непрозрачное изображение.

## Системные требования

### Готовая сборка

- Windows 10 или Windows 11, 64-разрядная версия
- Частная локальная сеть, общая для ПК Windows и устройства воспроизведения
- Совместимый DLNA-видеоплеер
- Поддерживаемый NVIDIA GPU и актуальный драйвер NVIDIA для режимов ИИ в реальном времени

Готовый пакет содержит необходимые компоненты среды выполнения. Для обычного использования упакованного приложения отдельная установка CUDA Toolkit не требуется. Для работы GPU по-прежнему необходим драйвер дисплея NVIDIA.

Без совместимого NVIDIA GPU:

- Обычная передача DLNA остаётся доступной в режиме `OFF`.
- Автономное преобразование RVM может использовать модель FP32 ONNX через ONNX Runtime CPU EP.
- Режимы Alpha Packed, Alpha WebM VP9 и Chroma Key в реальном времени отключаются.

## Установка

1. Скачайте последнюю версию установщика Windows x64 со страницы **Releases** Repository.
2. Запустите установщик.
3. Запустите `r800zzXRdlnaServer`.
4. Если появится запрос брандмауэра Windows, разрешите доступ в **частных сетях**.

Установщик имеет сравнительно большой размер, поскольку GPU-сборка включает поддержку ONNX Runtime CUDA, компоненты среды выполнения CUDA/cuDNN, библиотеки FFmpeg и модели RVM.

## Основное использование DLNA

1. Выберите папку с помощью **Выбрать папку с видео...**, добавьте отдельные файлы через **Выбрать видеофайл...** или используйте оба способа.
2. Выберите режим вывода:
   - **Alpha packed**
   - **Alpha WebM VP9**
   - **Chroma Key**
   - **OFF**
3. Проверьте публикуемый IPv4-адрес.
4. Выберите **Запустить DLNA-сервер**.
5. Откройте совместимый DLNA-плеер в той же локальной сети.
6. Выберите `r800zzXRdlnaServer`, затем выберите видео.

В журнале сервера отображаются обнаружение DLNA, запросы описания устройства, запросы списка медиа, запросы воспроизведения и ошибки worker. Кнопка **Очистить журнал** очищает отображаемый журнал.

## Преобразование видео

Встроенный конвертер может создавать:

- MP4 с хромакеем
- Alpha WebM VP9
- Alpha Packed MP4

Предлагаемое имя выходного файла содержит время начала преобразования:

```text
movie_RVM_ChromaKey_202609210542.mp4
```

Ход преобразования отображается как количество выходных кадров. Сначала конвертер записывает данные во внутренний временный файл и создаёт запрошенное выходное имя только после успешного завершения кодировщика и контейнера. Журнал преобразования сохраняется рядом с выходным файлом.

Если доступно ускорение NVIDIA, преобразование использует NVDEC, CUDA, RVM через ONNX Runtime CUDA EP и, где применимо, NVENC. В противном случае используются программное декодирование FFmpeg, модель FP32 RVM через ONNX Runtime CPU EP и программное кодирование.

## Встроенный видеоплеер

Команда **Видеоплеер...** открывает локальное видео независимо от выбранных для DLNA файлов.

Элементы управления:

- Воспроизведение/пауза
- Полоса перемотки
- Текущее и общее время
- Переключение полноэкранного режима
- Отображение левой половины SBS
- Space: воспроизведение/пауза
- Стрелка влево/вправо: перемотка на пять секунд
- Escape: выход из полноэкранного режима или закрытие плеера в оконном режиме

Для поддерживаемых кодеков плеер сначала пытается использовать NVIDIA NVDEC, а при невозможности переключается на программное декодирование.

## Обработка звука

- Режим `OFF` передаёт исходный файл без изменений; аудиокодек обрабатывает принимающий плеер.
- Вывод MPEG-TS в режимах Alpha Packed и Chroma Key использует звук AAC.
- Вывод Alpha WebM VP9 использует звук Opus.
- При необходимости можно перекодировать другие исходные аудиоформаты, декодируемые FFmpeg.
- Многоканальный звук сводится в стерео; монофонический остаётся монофоническим.

## Сборка из исходного кода

### Требования

- Windows 10 или Windows 11, 64-разрядная версия
- Visual Studio 2022 с компонентом **Разработка классических приложений на C++**
- CMake 3.24 или новее
- NVIDIA CUDA Toolkit 12.8
- Подключение к интернету во время загрузки зависимостей сборки

### Сборка

Откройте командную строку в корне Repository и выполните:

```bat
setup_dependencies.bat
build.bat
```

`setup_dependencies.bat` загружает закреплённые версии зависимостей разработки и официальные модели RVM ONNX. `build.bat` настраивает и собирает проект с помощью CMake и NMake.

Созданные файлы находятся в:

```text
build_cuda_ep\bin\r800zz_dlna_server.exe
build_cuda_ep\bin\r800zz_ai_worker.exe
build_cuda_ep\bin\rvm_mobilenetv3_fp16.onnx
build_cuda_ep\bin\rvm_mobilenetv3_fp32.onnx
```

Текущая сборка закрепляет общий пакет FFmpeg на версии `N-124714-g49a77d37be`. Не заменяйте закреплённый пакет плавающей последней версией без проверки требований к драйверу NVIDIA и API NVENC.

## Реализация

Путь обработки NVIDIA в реальном времени:

```text
FFmpeg NVDEC
    -> предварительная обработка CUDA
    -> ONNX Runtime CUDA EP / RVM
    -> упаковка альфа-канала CUDA или композиция хромакея
    -> FFmpeg NVENC
    -> MPEG-TS / DLNA
```

Путь настоящего альфа-канала WebM подготавливает данные YUVA420P на CUDA, передаёт их в повторно используемые кадры CPU и использует `libvpx-vp9`, поскольку графические процессоры NVIDIA не обеспечивают аппаратное кодирование VP9.

FFmpeg используется через следующие библиотеки C и общие DLL:

- `avformat`
- `avcodec`
- `avutil`
- `swresample`
- `swscale`

## Известные ограничения

- Для конвейера ИИ в реальном времени в настоящее время требуется NVIDIA GPU.
- Ускорение на GPU AMD и Intel не реализовано.
- Кодирование альфа-канала WebM VP9 сильно нагружает CPU и может не поддерживать исходную частоту кадров.
- Поддержка альфа-канала и хромакея различается между DLNA/XR-плеерами.
- В настоящее время приложение предназначено для Windows x64.
